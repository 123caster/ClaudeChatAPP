# Happy 风格流式消息滚动稳定性设计

## 目标

修复 AI 流式回答期间聊天页面反复跳动的问题。用户停留在最新消息附近时，应持续看到最新内容平稳出现在输入框上方；用户上滑阅读历史后，任何流式更新都不得改变当前阅读位置。

本次只修改 Mobile 聊天列表的渲染和定位机制，不修改 Gateway、事件协议、数据库、Markdown 内容或流式开关。

## 已确认根因

当前聊天页使用普通 `FlatList`。`assistant.delta` 每 50ms 合并更新后，消息高度发生变化，`onContentSizeChange` 会每 120ms安排一次 `scrollToEnd`。Markdown 段落、代码块和工具结果持续增高时，列表不断测量末端并重新定位视口，形成可见抖动。

Happy 将最新消息放在倒置列表的偏移 `0`，依靠原生 `maintainVisibleContentPosition` 保持锚点，内容尺寸变化不触发 JS 主动滚动。本项目采用同一原则。

## 列表结构

- 领域层的 `timeline` 继续保持从旧到新的顺序，不改变缓存和状态模型。
- 展示层先截取最新窗口，再反转为从新到旧的数据，传入带 `inverted` 的 `FlatList`。
- 稳定的消息 `key` 保持不变，流式回答更新同一行，不反复卸载或创建消息组件。
- 倒置后，`ListHeaderComponent` 位于视觉底部，用于最新消息后的留白；“加载更早消息”改为 `ListFooterComponent`，位于视觉顶部。
- 输入框上方留白使用倒置容器对应的顶部内边距，确保最后一条消息不被输入框遮挡。

## 滚动规则

- 列表配置 `maintainVisibleContentPosition={{ minIndexForVisible: 0, autoscrollToTopThreshold: 200 }}`。
- 进入会话时列表默认处于偏移 `0`，不再用定时器反复跳到末尾。
- 用户发送消息或点击“最新消息”时，仅执行一次 `scrollToOffset({ offset: 0 })`。
- `onContentSizeChange` 只允许记录尺寸，不调用 `scrollToEnd`、`scrollToOffset` 或延迟滚动任务。
- 倒置列表中 `contentOffset.y` 表示距最新消息的距离：接近 `0` 时视为正在跟随；超过阈值时视为阅读历史。
- 用户阅读历史期间，新内容仅更新“↓ 最新消息”提示。滚回偏移 `0` 或点击提示后恢复原生跟随。
- 键盘和输入框高度变化只改变可用视口及底部留白，不触发消息列表末端重算。

## 历史消息与流式渲染

- 保留当前 50 条初始窗口和每次 50 条历史消息的策略。
- 加载更早消息时，旧数据只增加在倒置列表的远端，由原生锚点保持当前可见文字位置。
- 保留 50ms 的 `assistant.delta` 合并窗口，避免逐 token React 更新。
- 不增加额外节流等待；稳定性来自原生锚点，而不是隐藏或延迟模型输出。

## 代码边界

- `BasicChatScreen.tsx`：倒置列表、数据顺序、入口定位、最新消息按钮、历史入口和滚动事件。
- `chat-scroll.ts`：倒置偏移判断和原生锚点配置所需的纯函数；删除仅服务于周期性尾部滚动的逻辑。
- `chat-scroll.test.ts`：覆盖倒置偏移、用户接管、单次跳转和历史窗口行为。

不引入新的列表依赖；继续使用 React Native `FlatList`，降低发布风险。

## 验收标准

1. 进入任意长会话时直接显示最后一条消息，页面无先显示顶部再跳到底部的过程。
2. AI 输出长回答、Markdown、代码块或工具结果时，最新内容平稳出现在输入框上方，无周期性抖动。
3. 用户上滑后，流式输出不改变阅读位置，只出现“↓ 最新消息”。
4. 点击“↓ 最新消息”只执行一次平滑跳转，随后恢复底部跟随。
5. 加载更早消息后，当前阅读文字和屏幕偏移保持不变。
6. 键盘打开、关闭及输入框增高时，最后一条消息始终完整位于输入框上方。
7. Mobile Jest、TypeScript、ESLint 和格式检查通过；本阶段不修改或部署 Gateway。
