# 手机聊天滚动稳定与图片预览设计

## 目标

解决 AI 流式回答期间聊天列表反复跳动的问题，并将用户发送的图片改为紧凑缩略图；点击缩略图后可全屏查看原图。改动仅涉及 App 展示与滚动控制，不修改 Gateway 协议、图片上传流程或数据库结构。

## 滚动状态

聊天列表继续使用三态控制：

- `FOLLOWING`：用户位于列表底部，允许新内容触发轻量补位。
- `READING_HISTORY`：用户开始拖动、惯性滚动或离开底部，禁止自动滚动。
- `JUMPING_LATEST`：首次进入会话、发送消息或点击“最新消息”后执行一次定位，完成后进入 `FOLLOWING`。

`onScrollBeginDrag` 必须立即进入 `READING_HISTORY`，同时增加滚动任务序号，使此前通过定时器或 `requestAnimationFrame` 排队的任务失效。程序触发的滚动不得覆盖用户手势状态。用户重新滚到距离底部 64dp 以内时，才恢复 `FOLLOWING`。

## 流式更新与底部跟随

Gateway 的流式分段继续按短时间窗口合并，减少 React 状态更新和 Markdown 重排次数。内容高度变化时，仅当列表处于 `FOLLOWING`、没有用户手势且没有更晚的补位任务时，才调度一次非动画底部补位。同一个刷新窗口内的多次变化合并为一次任务。

进入会话、发送消息和点击“最新消息”使用一次显式跳转。用户处于 `READING_HISTORY` 时，新内容只更新“最新消息”提示，不调用 `scrollToEnd`。输入框高度或键盘安全区变化也遵循相同规则，确保最后一条消息位于输入框上方，同时不打断历史阅读。

## 图片缩略图

单张图片从首次布局开始使用固定约 `132 x 98dp` 的紧凑外框，采用圆角并以 `cover` 方式裁切。多张图片使用相同尺寸组成网格。加载中、加载成功和加载失败共用同一外框尺寸，失败状态在框内提供重试入口，避免图片解码完成后改变消息高度。

图片消息保留现有本地预览和远端资源地址，不复制或长期保存新的原图。图片资源不可用时，聊天列表仍保持稳定，并显示可理解的失败状态。

## 全屏预览

点击缩略图打开原生 `Modal`。预览层使用深色背景，图片以 `contain` 方式完整适应可用屏幕，不裁切。用户可通过右上角关闭按钮、点击背景或 Android 返回键退出。预览不提供双指缩放、下载或编辑功能。

## 组件边界

- `BasicChatScreen` 负责滚动状态、任务取消、底部判定和“最新消息”行为。
- `chat-scroll` 提供纯函数状态转换和可测试的滚动调度判定。
- `MessageAttachments` 负责缩略图稳定布局、失败重试和全屏预览状态。
- 消息及附件继续使用稳定标识，流式文本变化不得更换列表项 `key`。

## 测试与验收

- 单元测试覆盖用户拖动后取消旧补位任务、历史阅读期间禁止跟随、回到底部后恢复跟随，以及显式跳转完成后的状态转换。
- 组件测试覆盖固定缩略图尺寸、点击打开预览、三种关闭方式和加载失败不改变外框。
- 长回答流式输出时，从底部上滑后页面不回跳；停留底部时回答平稳跟随。
- 图片加载前后当前文字位置不漂移，消息内仅显示紧凑缩略图。
- 键盘弹出、输入框增高及点击“最新消息”后，最后一条消息完整显示在输入框上方。
