# 公开仓库敏感配置清理设计

## 目标

公开源码、GitHub 与 Gitee 的所有现有分支和可达提交不得包含真实 Gateway 地址、带地址的证书路径、本机绝对路径或真实凭据。App 继续支持连接私有 Gateway，但地址只能在本地构建环境中提供，不能写入受版本控制的文件。

## 当前边界

- GitHub 和 Gitee 保留各自现有分支集合，不新增、删除或合并分支。
- 两个远程分别重写，避免把一方独有分支复制到另一方。
- 清理覆盖分支与标签的完整可达历史；Pull Request 内部引用、第三方 Fork、他人本地克隆和平台缓存不受普通强制推送控制。
- 本次地址不是访问凭据，但公开仓库仍按敏感数据清理流程处理。API Key、令牌和证书私钥若被发现，必须先撤销或轮换，再重写历史。

## App 配置

`apps/mobile/src/config/gateway.ts` 改为读取 `process.env.EXPO_PUBLIC_GATEWAY_URL`，不提供真实地址或可意外连接的默认值。配置值必须是合法的 `https://` 地址，并在导出前移除末尾斜杠。

缺少或无效配置时，App 不发起网络请求，连接页显示“未配置服务器地址”，同时保留重新检测入口。开发和 Release 构建通过本地 `.env.local` 或构建进程环境提供地址；`.env.local` 继续被 Git 忽略。仓库只提供使用 `https://gateway.example.com` 的 `.env.example`。

测试统一使用 `example.com`、RFC 5737 示例 IP 或回环地址，不再复用生产地址。测试覆盖合法 HTTPS、缺少变量、HTTP 和非法 URL。

## 运维模板

Nginx、证书续期和健康检查文件不再写死公网地址。Shell 安装脚本要求调用方提供 `CLAUDECHAT_PUBLIC_HOST`，并将 `__CLAUDECHAT_PUBLIC_HOST__` 渲染到临时配置后安装。变量只允许主机名或 IP 字面量，拒绝路径分隔符、空白和 Shell 元字符。

仓库内的示例 Nginx 配置、证书目录和设计文档统一使用 `gateway.example.com`。服务器上的正式配置不由 Git 历史清理自动修改，避免影响正在运行的 Gateway。

## 历史重写

1. 记录 GitHub、Gitee 当前分支和标签名称及提交哈希。
2. 将当前源码参数化改动提交到功能分支，并先执行完整质量门禁。
3. 为两个远程分别创建临时镜像克隆，清理词表存放在仓库外。
4. 使用支持 `--sensitive-data-removal` 的 `git-filter-repo` 对全部非二进制历史执行文本替换；真实地址替换为 `gateway.example.com`，本机私密路径替换为通用占位符。
5. 在镜像中扫描所有分支、标签、提交消息和历史 Blob，真实值必须为零命中。
6. 按重写前记录的分支集合逐分支强制推送，再推送原有标签；不使用会删除未知远程引用的无条件镜像推送。
7. 从 GitHub 和 Gitee 各建立一个全新验证克隆，再次扫描所有可达历史并核对分支数量、名称和提交树。
8. 删除临时镜像、清理词表和旧对象备份，防止本机继续保留可误推的历史。

重写后所有相关提交哈希都会改变。旧克隆不得直接 `pull` 后推送，必须重新克隆或严格重置到新远程历史，否则会重新引入已清理内容。

## 验证

- 全仓构建、测试、TypeScript、ESLint、Prettier 和 `git diff --check` 通过。
- 当前源码不存在真实地址、真实凭据、私钥头、数据库、APK 或本机配置。
- GitHub 与 Gitee 的分支名称、数量与重写前一致。
- 两个全新验证克隆中，针对清理词表扫描所有可达提交均为零命中。
- 当前功能分支仍包含完整 `apps/mobile`、`apps/gateway`、协议和数据库源码。
- App 在未配置地址时给出明确提示；配置示例地址时请求基址正确规范化。

## 平台残留说明

根据 GitHub 官方说明，强制推送后，旧提交仍可能通过旧 SHA、Pull Request 引用、Fork 或缓存短期可达。分支和标签历史清理完成后，如旧 SHA 仍能访问，只能继续处理相关 Fork，或向平台支持提交缓存与 Pull Request 引用清理申请。由于服务器地址不是不可轮换的访问凭据，平台可能不会受理彻底清缓存请求；本次验收以两个远程所有分支、标签和新克隆的可达历史零命中为准。
