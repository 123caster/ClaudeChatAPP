# ClaudeChatAPP 多附件、语音输入与舒适界面设计

> 日期：2026-09-14
>
> 状态：交互与技术方向已确认，等待书面规格复核
>
> 参考：用户提供的 Happy 风格会话列表与聊天页截图；浏览器原型视觉方向 A

## 1. 目标与边界

本阶段为 Android 客户端增加多图片、多文件和语音转文字能力，并将会话列表与聊天页调整为轻盈、白色、舒适的移动端工作台。附件只服务于当前提问，不自动写入项目工作区。聊天记录保留附件名称、类型、大小和图片压缩缩略图；原始附件在模型处理后删除。

本阶段不支持相机拍摄、发送原始语音消息、压缩包、可执行文件、安装包、跨会话复用附件，也不改变现有项目工作目录和工具权限规则。

## 2. 已确认的产品规则

- 每次消息最多 9 个附件，图片与文件合计计算。
- 单张图片最大 10 MB，单个文件最大 20 MB，总量最大 40 MB。
- 图片支持 JPEG、PNG、GIF、WebP；相册中的其他格式在客户端可转换时转为 JPEG，否则明确拒绝。
- 文件支持代码与纯文本、Markdown、JSON、CSV、PDF，以及现代 Office 文件 `.docx`、`.xlsx`、`.pptx`。
- 原始附件在本轮任务结束后立即删除；未发送、断线或异常遗留文件最多保留 24 小时。
- 语音只在手机本地或系统识别服务中转写为文字。用户点击“使用文字”后才写入输入框；原始录音不上传、不保存。
- 当前会话模型不支持图片时，Gateway 使用“默认多模态模型”识别，再把结构化结果交给当前会话模型；不会永久切换会话模型。

## 3. 视觉与交互

### 3.1 会话列表

页面采用暖白背景、纯白列表面、深灰正文、青绿色主操作色，避免大面积单色装饰。顶部仅保留产品入口、标题和设置。会话按时间分组，行内显示标题、工作目录/分支、状态和时间；底部使用参考图中的悬浮新任务输入入口。

### 3.2 聊天页面

顶部为返回、会话标题、工作目录/分支和品牌标识。AI 内容采用近乎全宽的无气泡阅读布局；用户消息使用右侧浅色气泡。Markdown、表格、代码块继续移动端渲染，不显示源码标记。

输入区固定在系统键盘正上方。消息列表底部留白由输入区实测高度与安全区动态计算，保证最后一条消息可完整滚动到输入框上方。输入框从 1 行增长到 6 行，之后内部滚动。

左下角 `+` 打开“相册 / 文件”底部菜单；附件托盘位于输入框内部上方并横向滚动。每项显示缩略图或文件图标、名称、大小、上传状态、移除按钮；失败项可以单独重试。发送按钮只有在存在文字或附件，且所有附件上传完成时可用。

麦克风按钮进入听写态，显示实时波形、转写文字、“取消”和“使用文字”。听写不会自动发送。语音态、附件态和键盘态都不得遮挡消息。

### 3.3 滚动规则

沿用 `FOLLOWING / READING_HISTORY / JUMPING_LATEST` 三态控制。流式文本、附件缩略图加载和输入区高度变化只在 `FOLLOWING` 状态补位；用户拖动后立即进入 `READING_HISTORY`，只更新“最新消息”提示。点击提示或用户发送消息后执行一次有界跳转。

## 4. 系统设计

### 4.1 协议

新增 `AttachmentSummary`：`id`、`kind`、`name`、`mimeType`、`size`、`status`、`previewAvailable`、`createdAt`。`Message` 增加 `attachments` 数组。`CreateSessionRequest` 与 `SendMessageRequest` 增加可选 `attachmentIds`，并允许附件消息的文字为空，但文字和附件不能同时为空。

新增接口：

- `POST /v1/attachments`：单文件 multipart 上传，返回附件摘要。一次上传一个文件，便于显示进度、取消和单项重试。
- `POST /v1/attachments/:attachmentId/delete`：删除尚未绑定消息的附件。
- `GET /v1/attachments/:attachmentId/preview`：鉴权返回压缩图片缩略图。

所有写操作保留 `requestId` 幂等语义。附件 ID 必须属于当前设备、目标会话或待创建会话请求，不能跨消息复用。

### 4.2 数据库与存储

新增附件表，保存消息关联、设备关联、原始显示名、服务端随机文件名、类型、大小、状态、原件到期时间和缩略图路径。消息创建与附件绑定在同一事务中完成。模型表增加 `supports_images`、`supports_documents` 和 `is_multimodal_default`；数据库迁移只增列/增表，不重建现有模型、会话和消息。

运行文件放在 Gateway 数据目录下独立的 `attachments/originals` 与 `attachments/previews`，目录权限限制为服务账号。原件不使用用户文件名落盘。图片缩略图最长边限制为 320 px，并移除 EXIF。文档历史只保存元数据，不保存正文预览。

### 4.3 Gateway 服务边界

- `AttachmentService`：上传、类型识别、限额、状态、绑定、删除和定期清理。
- `AttachmentContentService`：图片规范化，PDF 内容块，文本安全读取，Office 结构化文本提取和最大字符限制。
- `MultimodalRouter`：判断会话模型能力；必要时调用默认多模态模型，将图片识别为带文件名引用的结构化文本。
- `SessionService`：只接收已验证且上传完成的附件，持久化用户消息后启动 Claude；无论成功、失败或取消都在安全时点释放原件。

图片与 PDF 使用 Agent SDK 支持的结构化 `SDKUserMessage` 内容块。普通文本和 Office 提取结果使用文档文本块。确需 Claude 工具读取的临时文件通过 SDK `additionalDirectories` 暴露，只允许本次请求的随机目录，并在任务结束后撤销和删除。

### 4.4 移动端组件

- `AttachmentPicker`：相册多选与文件多选，负责客户端即时限制。
- `AttachmentUploadQueue`：逐项上传、进度、取消、重试和断线恢复。
- `AttachmentTray` / `MessageAttachments`：编辑态附件和历史附件展示。
- `VoiceComposer`：麦克风权限、开始/停止、实时转写、取消和确认。
- `ChatComposer`：统一管理文字、附件、听写、发送条件和键盘高度。

附件草稿保存在本地缓存中；应用重启后只恢复仍有效的服务端附件 ID，过期项提示重新选择。成功发送后清空当前草稿。

## 5. 错误与安全

客户端选择阶段先拦截数量和声明大小，Gateway 以真实接收字节数再次校验。服务端同时检查扩展名、MIME 和文件头，拒绝路径字符、双扩展伪装、压缩包、可执行内容和超限 Office 解包结果。

上传失败不清除文字和其他附件；发送失败保留整个草稿。多模态模型不可用、文件解析失败、附件过期或权限拒绝均给出明确中文错误，不静默降级为纯文本。日志只记录附件 ID、归类、字节数、耗时和错误码，不记录正文、图片数据、原始路径、令牌或 API Key。

## 6. 测试与验收

协议测试覆盖空消息条件、数量/大小边界和附件 DTO。数据库测试覆盖迁移、事务绑定、消息查询、会话删除级联和过期清理。Gateway 测试覆盖鉴权、伪造类型、恶意文件名、幂等、跨设备/跨会话访问、图片/PDF内容块、Office 提取、模型回退以及成功/失败/取消清理。

移动端测试覆盖相册/文件权限、多选上限、上传进度、取消与单项重试、草稿恢复、语音转写与拒绝权限、发送条件、历史附件预览、键盘避让和三态滚动。

真机验收至少包括：9 个混合附件成功发送；超限即时提示；弱网中断后续传/重试；多图由默认多模态模型识别并回到原会话模型；语音文字可编辑后发送；键盘打开时输入框和最后一条消息均完整可见；浏览历史时流式输出不抢夺滚动位置。

交付前运行全量测试、TypeScript、ESLint、Prettier、Release 构建、APK 元数据/签名/Bundle 检查、服务器 Gateway 数据保护部署和真机安装验证。构建后删除临时源码副本、临时 Gradle 缓存和生成的共享包，只保留最终 APK。
